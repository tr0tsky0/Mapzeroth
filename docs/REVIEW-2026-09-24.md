# Mapzeroth Rebuild — Cruft Review, 2026-09-24

Status: batches 1, 2 and 3 are committed on `rebuild` (not pushed); batches 4 and 5 are not started. Batches are picked from the "Order of attack" at the end;
each batch ships with an in-game checklist for both flavours.

Scope: `Mapzeroth-Rebuild` (the two-toc addon). The old shipped addon under `../Mapzeroth/` and
the `tools/MapzerothDataTools` dev addon are reference only, except where the rebuild depends on
them. Baseline at review time: the default Forever test run plus the Modern smoke and picker tests
all pass.

## Architecture

**The two .toc files differ only in the data block.** Header lines (Interface, Title, Notes) and
comments differ, then Forever lists `Data\Forever\*` and Modern lists `Data\Modern\*`. The
Constants, Locales, Options, engine, UI and Core lists are identical and in the same order. No
other divergence. Forever's toc includes an empty placeholder `Geometry.lua`, which is harmless.

**File responsibilities, in load order.**

- `Constants.lua`: tuning numbers, plus some flavour-specific tables that have drifted in (finding 8).
- `Locales.lua` / `Locales_UI.lua` / `Locales/*.lua`: the string table with client-locale then English fallback.
- `Options.lua`: settings definitions, clamping, change listeners, backed by `MapzerothRebuildDB.settings`.
- Data files: `addon.Nodes.<group>`, `addon.Edges`, `addon.Containers`, `addon.Abilities`, plus
  Forever-only `Cities/Towns/Professions/ProfessionRanks/ClassWeapons/RidingSkills/PathFactors/LeyLineSpell`
  and Modern-only `CityPlaces/Instances/InstanceNodeAliases/CURRENT_EXPANSION/SEASONAL_DUNGEONS/DEFAULT_MOUNT_BONUS`.
  Both ship `Geometry`.
- `World.lua`: container tree from dotted paths, inherited flags, map-to-container lookup.
- `NodeNames.lua`: name resolution from client APIs, kind patterns and locale strings, cached per node.
- `Hearth.lua`, `FlightKnowledge.lua`: the two pieces of live per-character state (bind location,
  found flight points and fare factors).
- `Trainers.lua`, `Relevance.lua`: picker relevance rules.
- `PlayerAbilities.lua`: the player context snapshot and the "anywhere to node" teleport list.
- `Equipment.lua`, `MovementSpeed.lua`, `EdgeRequirements.lua`: equip/restore state machine, ground
  and flight speed, requirement checkers.
- `TravelGraph.lua`: adjacency list per context: authored edges filtered by requirements, cached
  static geometry (walk, gate, fly), teleports, plus start and waypoint injection.
- `Pathfinder.lua`: label-setting Dijkstra with phase state, ticket-in-the-air state and optional
  fare budget; step collapsing.
- `Search.lua`, `Destinations.lua`, `Sections.lua`: the picker's entries, search scoring, accordion layout.
- `Location.lua`, `Journey.lua`: player start and waypoint; session, pricing, plan, readable steps, hints.
- `Navigation.lua`, `MapRoute.lua`: frame-free trip tracking and route geometry.
- `UI/`: Theme (the only styling layer), RouteLines and MinimapLines (drawing), Panel (docked
  picker), Navigator (trip window), OptionsPanel.
- `Core.lua`: events, login init, slash command, the `MapzerothAddon` global for the dev tool.

**Data flow.** Login: `World:Build` → `FlightKnowledge:Load` → `Theme:Init` → options page →
`Panel:Init`. Map open: `GetPlayerContext` → `Destinations:Build` → `Sections:Build`. First section
opened or a pick: `GetPlayerStart` → `Journey:Build` (→ `TravelGraph:Build` → `AddStart`) →
`Pathfinder:FindCosts` or `FindPath` → `CollapseSteps` → readable steps. Start: `Navigation:Start`
→ Navigator ticks `Sample`/`Update` → `Render` feeds RouteLines, MinimapLines, Equipment and the
panel highlight.

**Hot paths.**

- Navigator `OnUpdate` every 0.5 s: `Navigation:Update` (several world-position projections per tick) and `Render`.
- MinimapLines `OnUpdate` every 0.1 s while a trip runs: a full redraw with projections and line pooling.
- Panel `OnTextChanged`: `Search:Query` over every entry per keystroke, then `Render`.
- Per destination click: two full `TravelGraph:Build` calls and two or three Dijkstra runs (finding 4).
- Per map open: `Destinations:Build` over every node with a `C_Map.GetMapInfo` call each, plus name folding.
- `Pathfinder.run` inner loop: one string key concatenation and, when not dominated, one label table per relaxed edge.

## Findings, ranked by impact

Each finding: location, what/why, fix, flavours, risk, effort.

### 1. Hearthstone bind is saved account-wide but is per character

- Where: `Hearth.lua:12-19`, written from `Core.lua:42-50`.
- What: `SaveBind` writes `MapzerothRebuildDB.hearthstone` with no character key, while flights and
  fares are keyed per character. The second character to bind overwrites the first, so
  `GetBoundInnNode` returns another character's inn and hearthstone routes go to the wrong place.
- Fix: store under `MapzerothRebuildDB.hearthstones[characterKey]`, sharing the key helper with
  FlightKnowledge; read the old `hearthstone` field once as a migration fallback, then delete it.
- Flavours: both (Modern can't resolve an inn yet, but the bug is in shared code).
- Risk: low with the migration. Effort: trivial.

### 2. Holiday-gated edges can never open on Modern, for two independent reasons

- Where: `Constants.lua:66-70`, `PlayerAbilities.lua:64-82`, `Data/Modern/Edges.lua:224-229`.
- What: the data says `holiday = "Darkmoon Faire"` but the table is keyed `darkmoon_faire`, so the
  lookup is nil and the result is cached false for the session. Separately, the old addon waited for
  `CALENDAR_UPDATE_EVENT_LIST` before trusting `C_Calendar.GetNumDayEvents` (it returns nothing until
  the calendar has loaded); the rebuild dropped that and caches the first answer. The key mismatch
  existed in the old addon too (inherited), but the lost calendar priming is a regression.
- Fix: normalise the key in the generator (data side, preferred) or in the checker; register the
  calendar event in Core, call `C_Calendar.OpenCalendar` once, and don't cache a negative before the
  calendar is ready.
- Flavours: Modern (Forever has no holiday edges yet; the calendar fix is shared).
- Risk: low. Effort: trivial.

### 3. Phase-split containers are porous: the fly mesh and the phaseswitch edges ignore them

- Where: `TravelGraph.lua:181-211`, `Data/Modern/Edges.lua:269-275`, `Data/Modern/Containers.lua`.
- What: the `_art<N>` container suffix only stops walk auto-edges. The continent-wide fly pass joins
  every flyable node within range regardless of container, so `TIRISFAL_ZIDORMI_PAST` and friends get
  fly edges from ordinary nodes (visible in the shipped Geometry). The seven `phaseswitch` edges are
  live with no `phaseGroup` on any container, so Zidormi is a free ten-second hop between the two
  states. Meanwhile the `mapArtID` requirement has no checker, so those 18 edges fail closed as
  intended. Net effect: routes can enter a phase the player isn't in, then dead-end. This is the
  known-open phase item, but the fly-pass hole isn't in the notes.
- Fix: short term, have the generator put the same inert `mapArtID` gate on the phaseswitch edges,
  and have the fly pass skip nodes whose container path carries `_art` (or better, a real
  `phaseGroup`) until the phase model lands. Long term, the fly pass must respect `phaseGroup` like
  the walk pass respects containers.
- Flavours: Modern.
- Risk: low for the short-term gate; medium for the design change. Effort: trivial / significant.

### 4. Every destination click builds the whole graph twice and allocates tens of thousands of edge tables

- Where: `TravelGraph.lua:242-346`, `Journey.lua:186-195` and `Journey.lua:214-227`.
- What: `Build` copies every static geometry triple into a fresh `{from,to,cost,method,...}` table
  per call. On Modern that is roughly 40 to 60 thousand tables. `Panel:ShowRoute` creates a new
  session per click, and `flightHint` (and `missingFlightHint`) then calls `Journey:Build` again
  with a modified context to compute the "free" route, so it is two full builds plus up to three
  searches per click. Also `authored` (lines 280-283) rebuilds a string-keyed set every call though
  it is context-independent.
- Fix, in two steps: (a) stop dropping unfound taxi edges in `Build`; tag them `unfound = true` and
  give the search an `opts.ignoreUnfound`, so the hint runs on the same graph with no second build.
  Cache `authored` per `World.generation`. (b) later, let the search read the static triples directly
  with a per-container speed table instead of materialising them per build.
- Flavours: both (Modern feels it; Forever's graph is small).
- Risk: (a) low, tests cover hints; (b) medium, changes step shape through Pathfinder and Journey.
  Effort: (a) moderate, (b) significant.

### 5. Per-tick allocations and repeated projections while following a trip

- Where: `Navigation.lua:62-66`, `Navigation.lua:81-89`, `Navigation.lua:344-366`, `UI/MinimapLines.lua:167`.
- What: `distance()` builds a throwaway node table and does two client projections per call, and
  `Update` calls it for every later step (the skip loop), the jump check, and the current step,
  every 0.5 s. `yardsPerUnit` allocates three tables and does four projections per call; `Heading`
  calls it every tick and MinimapLines calls it every redraw at 10 Hz, though the answer per map
  never changes. `Sample` allocates a closure per tick and `active.last` a table per tick.
- Fix: project the sample to world coordinates once per `Update` and compare against cached node
  world positions; memoise `yardsPerUnit` per mapID; reuse the `last` table.
- Flavours: both. Risk: low. Effort: moderate.

### 6. Schema drift: two city models, two instance-naming schemes, two node-id conventions

- Where: `Destinations.lua:99-132` vs `Destinations.lua:179-193`; `NodeNames.lua:213-245`; `Sections.lua:49-97`.
- What: Forever describes a city as `Cities[key] = { mapID, x, y, taxi, area, faction }` with
  `CITY_<KEY>` centre nodes and entrance pairs; Modern describes it as
  `CityPlaces = { maps = {...}, expansion, hub }`. Forever instances are `INSTANCE_<NAME>` with
  `kind = "instance"` and `area`; Modern's are `INSTANCE_<journalID>` plus `Instances` and
  `InstanceNodeAliases`. Forever ids are `<KIND>_<PLACE>`, Modern's `<PLACE>_<KIND>`, so the
  prefix-based name fallback and the `TRANSPORT` prefix set in `groupOf` work only for Forever
  (Modern docks and portals all become group "other"). Shared code carries both shapes side by side;
  `addSettlements` and `addCityPlaces` are each a no-op on the other flavour.
- Fix: one city shape (`Cities` entries gain optional `maps`, `expansion`, `hub`; Modern's
  Places.lua emits that), one instance reference (`GetInstanceRef` already abstracts it; make
  Forever's `kind = "instance"` nodes carry a journal id or alias too, if Forever's client has the
  Encounter Journal, which is unconfirmed), and a suffix fallback next to the prefix one in NodeNames
  and `groupOf`.
- Flavours: both (code), Modern (data). Risk: medium, touches picker output. Effort: significant.

### 7. Flavour branching in shared code, keyed on data presence

- Where: `Sections.lua:116` and `Sections.lua:158-163` (`addon.CURRENT_EXPANSION`),
  `MovementSpeed.lua:24` (`not addon.RidingSkills`).
- What: no `if Forever then` exists, which is good. But two places pick a code path by whether a
  flavour-specific table happens to be loaded. That is the data-layer approach in spirit, yet the
  intent is inferred rather than declared, and a Forever dataset that later gains
  `CURRENT_EXPANSION` would silently switch pages.
- Fix: declare it in data: `addon.PickerLayout = "expansions" | "settlements"` in each flavour's
  Places/Pois file, and `addon.DEFAULT_MOUNT_BONUS = nil` explicitly in Forever with the rule
  "riding data wins when present" documented once.
- Flavours: both. Risk: low. Effort: trivial.

### 8. Flavour-specific data living in shared Constants

- Where: `Constants.lua:31-34` (`CLASS_TOKENS`, Forever's nine classes), `Constants.lua:66-70`
  (`HOLIDAYS`, Modern only), `Constants.lua:78` (`FREQUENT_FLIER`, Forever only).
- What: `CLASS_TOKENS` is missing Modern's four classes, which affects trainer naming and the
  validator (latent, since Modern has no trainer data yet). The others are inert on the wrong
  flavour but belong with their data.
- Fix: move all three into `Data/<flavour>` files and let the engine treat them as optional, as it
  already does for `LeyLineSpell`.
- Flavours: both. Risk: low. Effort: trivial.

### 9. The same Hearthstone item is a different method per flavour

- Where: `Data/Forever/Abilities.lua:46-48` (`method = "hearthstone"`) vs
  `Data/Modern/Abilities.lua:122-125` (no method), `PlayerAbilities.lua:153`.
- What: Modern's entry defaults to "teleport", so the step reads "Use Hearthstone" instead of "Use
  your Hearthstone to go to X". Cosmetic, but it is schema drift on item 6948 in both datasets.
- Fix: default the `Hearthstones` list's method to "hearthstone" in `GetKnownTeleports` (shared),
  or have the generator emit it.
- Flavours: Modern. Risk: low. Effort: trivial.

### 10. Two layered flight-knowledge predicates

- Where: `PlayerAbilities.lua:102-109`, `TravelGraph.lua:270-274`, `Journey.lua:199-210`, `Journey.lua:255-259`.
- What: `flightNodeFound` was the original strict rule; `flightUsable` was added on top for the
  "assume found" setting, and every consumer now branches on which one the context has. Tests build
  contexts with neither to mean "no rule". This is a patch on a patch.
- Fix: make the context always carry both, with `flightUsable` the single routing predicate and
  `flightNodeFound` the raw fact for hints; give the test `makeCtx` an explicit `flights = "all"`
  mode; delete the `if ctx.flightUsable then ... else` branches.
- Flavours: both. Risk: medium (test contexts change). Effort: moderate.

### 11. Dead code and unread data fields

- `Journey.lua:102` method `racial` exists nowhere in data or the other method tables.
- `UI/RouteLines.lua:197-212` `Show`, `SetCurrent`, `Clear` and `UI/MinimapLines.lua:229-231`
  `Clear`: only `Follow` is used by the addon.
- `Journey.lua:59-61` `Cost` and `Journey.lua:78-81` `EntryCost`, `UI/Theme.lua:233-235` `Strip`:

- Flavours: both. Risk: low. Effort: trivial.

### 14. Duplication inside the Modern data folder

### 17. WoW hygiene items

- `UI/Navigator.lua:199-215` and `:304-312`: `ui.frame:Hide()` can run in combat (the "arrived"
  auto-close and the off-route stop). The frame is the parent of a `SecureActionButtonTemplate`
  button. Hiding an unprotected parent is believed to be permitted, but unconfirmed on Forever's
  client; worth a combat test. If blocked, defer the hide to `PLAYER_REGEN_ENABLED`.
- `UI/MinimapLines.lua:101-103`: once the frame exists, `refreshIndoors` nudges the minimap zoom on
  every zone change for the rest of the session, trip or not. The nudge mirrors Blizzard's own
  indoor detection so it is a legitimate quirk workaround, but the events should be unregistered
  while no trip is followed.

- `UI/OptionsPanel.lua:135-142`: the `InterfaceOptions_AddCategory` fallback is dead on both clients

- No leaked globals found. The only globals are `MapzerothAddon`, the slash-command names,
  `MapzerothRebuildDB` and three named frames. Events are lifetime-registered by design. Frames are
  pooled or built once everywhere.
- Flavours: both. Risk: low. Effort: trivial.

### 18. `Destinations:Build` runs on every map open and does per-node client calls

- What: `GetZoneName` calls `C_Map.GetMapInfo` per node (uncached, unlike node names), then

  nodes per map open.
- Fix: cache zone names per mapID in NodeNames; rebuild entries only when faction, class or
  known-spell signature changes.
- Flavours: both. Risk: low. Effort: moderate.

## Order of attack

Ship together, safest first. Each batch gets an in-game checklist for both flavours when done.

1. **Quick wins, no behaviour change:** dead code (11), duplicate helpers with the cooldown guard
   unified (12), Modern duplicate edge and garrison factions (14), locale starter lines plus
   completeness test (15), validator checks (16), Core login branch and `Enum` guard consistency
   (17), structure nits (19), Forever indoor flags (20).
2. **Behaviour-changing bug fixes, flagged:** per-character hearth bind with migration (1), holiday
   key plus calendar priming (2), Hearthstone method default (9), phaseswitch gating and fly-pass
   exclusion for `_art` containers (3, short-term part).
3. **Performance:** single graph build per click via `ignoreUnfound` and cached `authored` (4a),
   projection caching in Navigation and MinimapLines (5), zone-name caching and entry reuse (18).
4. **Structure:** method vocabulary table (13), flight predicate consolidation (10), flavour tables
   out of Constants (8), declared picker layout (7).
5. **Design-level, needs a decision first:** city and instance schema unification (6), fly pass
   honouring phase groups (3, long-term part), static geometry shared with the search (4b).

**Where the work differed from the brief, and why**

- **4a:** the brief's design, not the review's (a): the second build for the flight hint stays, and each build got cheap.
  Ground speed is asked of one outdoor and one indoor container per context (the indoor one only if the data has an indoor
  container), and edge tables are cached per (`World.generation`, outdoor speed, indoor speed), at most 4 keys, oldest evicted.
  `authored` and the two sample containers are cached per generation (`factsForWorld`). A cache miss calls
  `staticGeometryFor()`, so `staticBuildCount` still counts geometry passes and the new `materialiseCount` counts misses.
  Per-node adjacency order is unchanged (authored edges first, then geometry), so every search sees the same graph.
- **5, `Heading` and `distance`:** `Heading` does not call `distance` (it uses `MapPoint` and `yardsPerUnit`), so there was no
  duplicate distance to pass along. What buildModel did compute twice was `nodeOf(step.nodeID)`; that is now once.
- **5, jump check:** the last known spot carries its own projected world position (`active.last.world`, copied at the end of
  each update) so the jump check does not project it again. Without that an update projected the player twice, not once.
  The projection is inside a `pcall`, like `MapPoint`. Nothing of the current sample outlives an `Update`.
- **5, `yardsPerUnit`:** the memo is also keyed on the provider function in use, because tests replace the provider and the
  same mapID has a different scale in each. A map that could not be measured is not memoised. `MinimapLines` needed no change
  of its own: `draw` and `rebuild` only call `YardsPerUnit`.
- **18:** `zoneName` does not memoise a nil (a map the client cannot name yet is asked again). `Fold` takes `memo` as a second
  argument and `Prepare` passes it; `Search:ClearFoldMemo()` is called from `ClearNodeNameCache`. `Destinations:Build` is not
  cached across opens, as briefed.
